# Security

## Scope and threat model

Metaharness is a **single-user system connected to that user's own backend**. A hub token grants full access to the shared memory and sync API. There are no tenants, per-agent permissions, MFA, or independently authenticated agent identities. A note's `source` is supplied by its writer; provenance labels describe recorded metadata, not a verified identity.

Protected data includes curated memory, journal notes, agent instruction files, hub credentials, and local agent stores. Relevant attackers include unauthenticated Internet clients, malicious websites, a compromised token holder, and malicious text or files placed in an otherwise readable agent store. The OS account, chosen static host/backend, installed agent CLIs, and build configuration must be trusted. A process already running as the owner can read the owner's files and credentials; this application is not an OS sandbox or a multi-user hosting platform.

The main boundaries are agent stores → harvest → journal; journal/curated files → generated agent context; memory → distillation model; app/CLI → authenticated hub → database; and setup → existing user configuration. Memory is untrusted data at every boundary. Compromising one agent or token can poison shared memory for the others.

## Credentials and storage

- Setup generates a bearer token from 32 bytes of OS cryptographic randomness (256 bits). Self-hosted and cloud hubs store a SHA-256 verifier, not the plaintext token. Python uses `hmac.compare_digest`; the shared JavaScript hub compares fixed-length hashes without a data-dependent early exit. JavaScript runtime timing is not a formal constant-time guarantee.
- CLI credentials are in `state/remote.json`; local server configuration, SQLite state, logs, generated briefs, and copied instruction files are private. Managed directories use `0700`, files use `0600`, and existing managed root-directory modes are repaired. Protected state writes use atomic replacement or no-follow opens. Agent instruction/configuration editors enforce private file permissions; they do not all use atomic replacement. Keep the surrounding account and backups private too.
- The native app stores the token in Expo SecureStore / iOS Keychain with device-only accessibility. The web app stores it in localStorage and warns beneath the token field. Disconnect removes it. Same-origin scripts and browser extensions with sufficient access can read web storage; use a dedicated trusted HTTPS origin and disconnect on shared computers.
- Cloud credentials belong in provider secret storage. Supabase's service-role key stays in the edge function, never the app. Database tables enable RLS without public read/write policies; the service role is the intended database caller. Cloudflare D1 is accessed through the Worker binding. These databases are not encrypted by application code; provider storage, access controls, and backups remain the operator's responsibility.
- The CLI and app require HTTPS for remote hubs. Plain HTTP is limited to loopback for local development. iOS ATS allows local networking and only explicit loopback HTTP exceptions; it does not enable arbitrary loads. `mh serve` itself is HTTP: put a properly configured HTTPS reverse proxy in front of a non-local deployment. CLI and app requests reject redirects to avoid forwarding bearer credentials.

Setup deliberately prints the token and private connection links to the user's terminal. Do not copy this output into logs, issues, screenshots, or shared shell recordings. The `/mcp/<token>` compatibility endpoint embeds a credential in a URL: proxies, cloud access logs, client history, and monitoring systems can capture it. Prefer `Authorization: Bearer …` where the client supports it, redact `/mcp/*` at the proxy, and avoid third-party URL previews. Application responses set `no-store` and `no-referrer`; these cannot erase a URL already recorded upstream.

`metaharness://connect?url=…&token=…` fills settings and requires an explicit Connect action. The app sanitizes navigation and never auto-connects. Another installed app can claim a custom scheme; manual entry is safer on an untrusted device. Web credentials in query strings/fragments are discarded before Router startup, but the initial request may already have reached host logs. Never distribute tokens in web URLs. Rotate a disclosed token by replacing the server verifier and reconnecting clients; tokens do not expire automatically.

## Exposed interfaces

| Interface | Access and data |
| --- | --- |
| Local MCP stdio | Invoked by the owner, no network listener or extra token. Context, curated sections, search, and remember tools inherit local account access. |
| `mh serve` | Loopback by default. Bearer-authenticated `/context`, `/search`, `/remember`, `/sync`, `/status`, `/openapi.json`, and MCP endpoints; optional token-in-path MCP compatibility. Stores synced files and queued notes in local SQLite. |
| Supabase | The same shared HTTP/MCP protocol through an edge function; PostgreSQL tables store synced files, queued notes, and the verifier. Apply **both** migrations, including `0002_pending_limit.sql`. |
| Cloudflare | The same shared HTTP/MCP protocol through a Worker; D1 stores the same data. No public table API. |
| Web/native app | Static web assets contain no hub credential. The app connects directly to the chosen hub. Only a token exactly equal to `demo` selects fictional, explicitly labelled sample data. |

All data and schema routes require authentication. An unauthenticated CORS preflight is necessary for browser bearer headers; it returns no memory and only allows known routes, methods, and headers. CORS permits loopback development origins and exact HTTPS origins explicitly listed in `MH_ALLOWED_ORIGINS`. It does not use a wildcard or cookies. CORS is a browser restriction, not authentication.

SQL uses bound values in SQLite, D1, and Supabase/PostgreSQL. Curated section names and sync filenames use fixed allowlists; a remote client cannot select an arbitrary filesystem path. The app renders Markdown as text/components, ignores raw HTML, and rejects executable link schemes. Exported pages include a script CSP and no-referrer policy. Production static hosts must also set the security headers described in [app/README.md](app/README.md), particularly `frame-ancestors`, which cannot be enforced by an HTML meta tag.

## Resource limits and data handling

HTTP bodies are limited to 8 MiB, synced files to 1 MiB each, notes to 16,000 characters, source/kind/scope metadata to 80 single-line characters, search queries to 512 characters, MCP batches to 20 calls, and acknowledgments to 1,000 IDs. Limits are checked again after secret redaction. The app caps responses at 2 MiB and bounds Markdown nesting. Oversized/invalid requests fail without exposing internal exception details.

New pending-note queues stop at 1,000 entries. Pending responses return at most 256 entries and 512 KiB, using small database pages; `/status` reports the full count. Older oversized entries are explicitly truncated in outgoing responses so they cannot permanently block draining, while their stored originals remain. Repeat sync to drain a backlog. The remote journal digest contains the latest complete observations that fit 1 MiB; the full journal stays local. Acknowledged remote records and local backups are retained, so operators must manage retention and disk usage.

Per-peer, per-process/isolate rate buckets permit 240 ingress requests, 120 authenticated requests, and 20 failed-authentication attempts per minute. Python separately limits preflights. Failed-authentication buckets do not consume the authenticated bucket; the shared ingress cap can still throttle callers behind the same proxy. Python also limits concurrent request threads to 32 and enforces an absolute 10-second request deadline. Cloud execution deadlines and connection limits come from the provider. The Worker caps each request at 48 D1 queries, below the [free-tier limit](https://developers.cloudflare.com/d1/platform/limits/), and returns 429 before exceeding its database budget. These in-memory limits are not distributed abuse protection: use provider/proxy rate limits for a public deployment. Forwarded client-address headers are not trusted outside the provider's documented request metadata.

Remember, harvest, sync, brief generation, and legacy reads scrub common API keys, bearer tokens, JWTs, private keys, credential assignments, and credential-bearing URLs. Harvesters reject symlinks in files or path components, non-regular files, and files larger than 1 MiB. Scrubbing is a best-effort pattern filter, not a secret detector: arbitrary secrets may not match, and old files/backups are not destructively rewritten. Review imported content, remove old sensitive copies, and rotate any real exposed secret.

Generated context and model prompts explicitly frame memory as untrusted data. Distillation runs in an empty temporary directory with inherited project instructions/MCP/hooks disabled; supported CLI flags disable tools and Codex filesystem/network permissions. Output is limited to exactly the four curated filenames, with duplicate/extra blocks rejected. The subscription CLI still sends the supplied memory to its model provider. Isolation flags fail closed on unsupported CLI versions. No paid model invocation was used to validate this audit.

These controls reduce tool execution and secret propagation; they do not prove a model cannot be persuaded to write false or malicious preferences. Connected agents must treat memory as evidence, preserve their own instruction hierarchy, and require user authorization for consequential actions. The `know-me` interview guidance follows the same rule. Memory is never automatically executed as a shell command. Subprocess calls pass argument arrays; launchd uses escaped plist serialization. Setup preserves marker-bounded user content and refuses ambiguous TOML edits instead of overwriting it.

## Audit results — 2026-10-29

Source and local runtime behavior were **reviewed against** [OWASP Top 10:2025](https://top10.owasp.org/2025/), [ASVS 5.0 Level 2](https://asvs.owasp.org/) requirements applicable to the hubs/web app, [MASVS 2](https://mas.owasp.org/MASVS/) control groups for iOS, and the [2025 Top 10 for LLM Applications](https://genai.owasp.org/llm-top-10/). This is a scoped engineering review, not certification or a claim that every standard requirement has been verified. CWE references identify weakness classes. Severity reflects this single-user threat model; dependency advisory severity is identified separately.

No unresolved **confirmed High/Medium implementation findings** remain from this review. This does not rule out undiscovered issues or misconfigured deployments.

Verification: 18 Python tests (including fake Claude/Codex/Gemini stores, temporary HOME, init/remember/harvest/tick, distill dry-run, stdio MCP, HTTP auth, redirects, modes, symlinks, and deadlines); both cloud adapter suites and seven shared-security tests; a real PostgreSQL engine regression through PGlite for RLS, parameterization, migrations, and queue limits; cloud TypeScript and native Deno checks; 46 app tests; web/iOS exports; eight browser combinations (390/1440, light/dark, demo/real hub) with zero console/page errors. App capture was imported locally by `mh tick` and acknowledged remotely. Additional browser tests cover hostile Markdown, URL sanitization, explicit connection, and HTTP rejection. See [app/VERIFICATION.md](app/VERIFICATION.md).

Not exercised: a signed iOS binary/device Keychain and OS link delivery, deployed edge runtimes/proxy settings/provider logs, distributed load, concurrent PostgreSQL sessions, or live model behavior. PGlite uses the PostgreSQL engine but is not a deployed Supabase service. The iOS export compiles JavaScript/assets, not an IPA. No deployment, login, cloud build/submit, or push was performed.

## Reporting a vulnerability

Use this repository's **Security → Report a vulnerability** private reporting option when available. If it is unavailable, open a minimal issue asking the maintainer for a private reporting channel; do not post credentials, personal memory, or a working public exploit. Include the affected revision, backend/runtime, synthetic reproduction, impact, and proposed mitigation privately. There is no published response-time guarantee or bug bounty. Rotate exposed credentials immediately rather than waiting for a report response.
